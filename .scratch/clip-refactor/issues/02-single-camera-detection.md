# 02: 跑通单路视觉变化检测闭环

**What to build:** Agent Server 为一路摄像头开启检测会话并指定基准图后，CLIP 比较新画面、保存变化候选五帧，通过 SSE 通知；Agent Server 获取图片并回执后，该路继续检测。沿用既有 HTTP/SSE 调用语义和术语，不把 VLM 调用移入 CLIP 服务。

**Blocked by:** 01 — 通过 TOML 启动服务并接入 Frigate。

**Status:** done

- [x] 可经 HTTP 开启和结束检测会话、设置基准图；保留既有基准来源及时间窗取帧能力，明确时间戳代表本机收帧时间。
- [x] 使用配置的离线 CLIP 模型和运行设备编码图像；变化判断相对于该路基准，模型不可用时给出明确状态或错误。
- [x] 持续变化确认时间与候选五帧间隔可配置、相互约束可校验，允许缩短时间以争取低延迟。
- [x] 候选图片可读取后才发送 SSE 通知；通知包含摄像头、检测会话、候选标识及图片地址，HTTP 可查询候选并获取图片。
- [x] 正常回执解除等待，可同时更新基准；没有基准、没有有效新帧或等待回执时不重复消耗检测推理。
- [x] 缺帧或断流后重置不再可完成的变化取帧过程，恢复视频后仍能产生新候选；不得用陈旧帧伪装实时画面。
- [x] 移植相关旧测试，并用确定性的图像编码替身验证开启会话、设置基准、通知、取图、回执与继续检测的完整链路，以及缺帧和无效推理回归场景。

**Validation:** 22 项任务 02 检测、真实 HTTP/SSE、模型和存储测试通过；任务 01 的 13 项回归通过，Pyright、Ruff 与构建通过。本机 MPS 已用现有 ViT-B/16 离线权重编码出 512 维归一化特征；另有真实 tiny CLIP CPU 测试。Standards 无问题；Spec 无实现阻塞项，并补齐了上传基准、结束会话和连接保持但无新帧的验收测试。Frigate 实际闭环与多路性能待任务 06。
