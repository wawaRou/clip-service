# 06: 完成原生 uv 环境下的运行验收

**What to build:** 用户可以按照简短说明在 M2 Max、Thor 和 Orin 的原生 uv 环境运行重构后的服务，并复现从 Frigate 画面到候选通知、回执与配置重载的流程。记录可用硬件上的实际检测频率和延迟，形成有依据的默认参数。

**Blocked by:** 05 — 运行中重载配置并增删改摄像头。

**Status:** ready-for-agent

- [ ] 检查平台安装指令与现有 uv 锁文件一致，沿用已确认的平台 Python、torch、torchvision 和安装源，不因统一运行方式而替换平台组合。
- [ ] 完成项目自动化回归、代码检查和打包验证；测试随前置任务建设，本任务负责整体验收而非首次补测试。
- [ ] 提供从配置到启动、开启会话、设置基准、订阅通知、获取图片、回执和显式重载的最小操作流程。
- [ ] 在实际可用的设备上验证正确的 MPS 或 CUDA 后端及真实模型推理，不以 CPU 或编码替身结果冒充硬件验证。
- [ ] 对可用的 Frigate 流记录单路和典型三路负载下的目标 FPS、实际 FPS、处理延迟和候选通知延迟，并注明模型、输入条件及测量起止点。
- [ ] 性能测量覆盖预处理、推理与结果处理；如果无法测量摄像头真实变化时刻，明确只测本机收帧后的延迟，不声称测得完整端到端延迟。
- [ ] 根据实测给出留有余量的目标 FPS、确认时间和五帧窗口建议；争取 1 秒内通知，但不宣称所有负载与平台必然达标。
- [ ] 分平台记录已验证、未验证及阻塞原因；设备或流不可用时保留未完成的实机验证项和复现步骤，不把环境组合已确认等同于新项目已跑通。
