# 03: 多路摄像头共享模型并按目标 FPS 检测

**What to build:** 多路摄像头在同一个服务进程中共享一份 CLIP 模型，各路默认以相同的全局目标 FPS 检测，按需单独覆盖。各路独立产生候选，用户能够查看目标与实际频率，并了解算力不足时的表现。

**Blocked by:** 02 — 跑通单路视觉变化检测闭环。

**Status:** ready-for-agent

- [ ] 单进程只加载一份 CLIP 模型；摄像头的缓存、基准、检测会话和等待回执状态相互独立。
- [ ] 全局配置目标检测 FPS，各路默认继承，支持按路覆盖；摄像头数量不写死，三路仅用作典型验证规模。
- [ ] 根据各路目标周期安排检测，执行时选择该路最新且未处理的有效帧；同一目标频率不要求同一瞬间执行推理。
- [ ] 算力和输入帧率充足时，各路实际检测频率维持在目标附近；无会话、无基准、无新帧或等待回执的摄像头不执行检测，不以重复推理补足 FPS。
- [ ] 过载时公平处理各路并跳过过期检测任务，不形成持续增长的旧帧队列，也不让某一路长期得不到处理。
- [ ] HTTP 状态暴露每路目标 FPS、实际 FPS 和处理延迟，说明统计窗口和延迟的起止点；各路事件可通过单个 SSE 订阅区分。
- [ ] 自动化验证覆盖相同目标 FPS、按路覆盖、状态隔离、暂停检测、输入不足及过载；使用可控时钟或可控推理耗时，避免依赖特定 GPU 性能的脆弱断言。
- [ ] 100 FPS 仅作为用户尚未实测的总能力预估，不设为默认值或验收前提。
