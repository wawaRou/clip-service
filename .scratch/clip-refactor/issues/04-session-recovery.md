# 04: 断线、回执超时和服务重启后恢复工作

**What to build:** 按 ADR 0002，Agent Server 在短暂断线后可以查到当前未处理候选；回执超时不会让检测永久卡住，重复或迟到回执不会破坏新状态。CLIP 重启后由 Agent Server 重建检测会话与基准。

**Blocked by:** 02 — 跑通单路视觉变化检测闭环。

**Status:** ready-for-agent

- [ ] SSE 重连后可通过 HTTP 查询当前未处理候选，支持 Agent Server 对账；不要求历史事件重放或持久消息队列。
- [ ] 回执等待期限可配置，并与图片保留期限分别处理；候选超时过期后解除等待，保留原基准继续检测。
- [ ] 明确记录同一变化可能再次产生候选；有效期内已成功处理的回执可以安全重试，迟到的旧回执不得更新新基准或清除新候选。
- [ ] 回执、设置基准、停止会话和超时处理之间具有一致的状态规则；耗时编码完成后重新核验所属会话和候选，失败不会被报告为成功。
- [ ] 候选状态与本地存储操作失败时保持可解释的一致状态；清理图片或候选记录不会留下永远无法解除的等待。
- [ ] 服务重启后恢复拉流和缓存，但不恢复活跃会话与基准；旧记录不会伪装成当前待处理候选，Agent Server 可以重新建立会话。
- [ ] 自动化验证覆盖断线对账、超时继续检测、重复和迟到回执、并发停止与基准更新、存储失败及重启重建；提供简短的 Agent Server 恢复说明。
