# Thor 解码帧驱动推理测量

2026-09-08，在 `8f2cb7f` 基础上的帧驱动调度工作区测量，未使用硬件解码。
模型为 Hugging Face 本地缓存中的 `openai/clip-vit-base-patch16`，CUDA、TF32，
权重仍为 float32。OpenCV 从 Frigate 解码为 BGR，CLIP 直接处理像素，JPEG 历史采样继续运行。

## 条件与口径

- 真实输入：`rtsp://192.168.3.245:8554/living_room_c225_sub`，1280 x 720 H.264。
- 每路 `inference_fps=30`、`ring_max_fps=30`；以下初次测量队列最多 3 帧，
  当前代码已改为 6 帧，对应复测见末节。
- 每路 episode 激活并设置真实帧基准，`similarity_threshold=-1`，保持连续推理。
- 每阶段预热 3 秒，单路测量 45.013 秒，三路测量 30.007 秒。
- 接收和推理 FPS 使用相应累计计数的差值除以本机单调时钟经过时间。
- 每 20 ms 采样健康状态，仅在完成计数变化时记录延迟；分位数并非逐帧完整分布。
- 延迟从本机接收解码帧计时至编码完成，不含摄像头采集与 Frigate 转发时间。
- 三路为三个独立读取器同时读取同一条真实流，共享一份模型，不是三台独立摄像头。

所有采样点流均新鲜、episode 持续推理、无推理错误。单路接近源视频的 25 FPS，
仍有偶发慢帧和少量丢弃，不能据此保证长期逐帧无损处理。三路总推理吞吐约 71.98 FPS，
各路均获得处理机会，队列有界；达到容量时主动丢旧帧。
测试阶段顺序执行，未固定 CPU/GPU 时钟，编码耗时的差异不单独解释为调度收益。

自动化回归另外覆盖到帧唤醒、突发帧消费顺序、限频、多路轮转、队列溢出、陈旧帧、
断流后的变化计时重置，以及会话、基准与配置变更后丢弃旧帧。
