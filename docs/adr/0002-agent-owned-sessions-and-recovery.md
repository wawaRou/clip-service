# 由 Agent Server 管理检测会话，采用可重建的运行状态

CLIP 服务负责比较画面与基准、生成变化候选，Agent Server 负责开启会话、指定基准、决定是否调用 VLM 并发送回执；双方沿用普通 HTTP 请求与 SSE 通知。为控制个人项目的恢复逻辑复杂度，CLIP 重启后恢复拉流与缓存，会话及基准由 Agent Server 重新建立；SSE 断线后通过 HTTP 查询当前未处理候选，不维护历史事件重放。

候选超过可配置的回执等待期限后过期，服务保留原基准并恢复检测；重复回执应可安全重试，迟到的旧回执不得影响新候选。这个取舍允许同一变化再次产生候选，也允许重启或候选过期导致旧通知无法继续处理；Agent Server 必须能够对账和重建会话，而不能假定所有历史通知都会被补发。回执等待期限与图片保留期限分别处理。
