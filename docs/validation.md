# 原生运行验收

本项目按 Mac、Thor、Orin 三组固定依赖使用原生 uv 环境。自动回归使用可控的视频和
编码边界验证业务规则；实机验收使用本地真实 CLIP 模型与 Frigate 转发流，两者分别记录。

## 复现完整闭环与测量

先按 README 安装对应 extra，确认本机模型目录和 Frigate 转发流可用。Mac 示例：

```bash
uv run --locked --extra mac python tests/manual_native.py \
  --model '/path/to/local/clip-vit-base-patch16' \
  --device mps \
  --frigate-url rtsp://127.0.0.1:8554 \
  --stream living_room_c225_sub \
  --output data/acceptance/mac-native.json
```

Thor / Orin 分别使用 `--extra thor` / `--extra orin`，指定 `--device cuda`，并将
Frigate 地址改为该设备能够访问的主机地址。模型路径必须为完整本地 CLIP 目录；脚本
开启离线加载，不自动下载模型。认证沿用 `CLIP_FRIGATE_USERNAME` 和
`CLIP_FRIGATE_PASSWORD`。基准、推理使用指定后端，GPU 不可用时失败，不回退到 CPU。

脚本在临时目录写 TOML，以当前 Python 启动独立服务进程；依次验证单路、热添加至
三路、设置基准、SSE 通知、五张候选图、HTTP 对账、幂等回执以及删除摄像头的结束
通知。运行后终止服务并清理临时配置、日志及候选图，只保留指定 JSON 报告。
三路使用同一个 Frigate 流的三个逻辑摄像头，验证共享模型与并发读取负载；这不等同于
三台独立物理摄像头的现场验收。手工逐步调用接口的流程见 [接口说明](api.md)。

默认每路目标 8 FPS，每阶段预热 3 秒后测量 10 秒；可用 `--fps`、`--seconds`、
`--warmup` 调整。吞吐阶段将相似度阈值设为 -1，避免等待候选回执暂停检测。
报告采用完成编码计数差除以本机单调时钟经过时间计算实际频率，包含整个检测循环对
吞吐的影响；每 0.2 秒采样最近完成帧的处理时长，不是每一帧的完整延迟分布。

通知阶段使用合成黑图作为基准，与真实视频画面比较，阈值为 0.9999，确认时间
0.3 秒、五帧间隔 0.075 秒。这用于稳定触发接口闭环，不用于验证真实场景的误报率。
延迟从该候选成功确认窗口的首个低相似度帧在 CLIP 主机的接收时间，算到同机 SSE
客户端收到完整事件；此前因缺帧丢弃的变化窗口不在此时间范围内。
包含确认等待、模型处理、候选写盘及通知；不包含物理摄像头采集、网络或 Frigate
转发前的延迟，不宣称测得真实画面变化的完整端到端延迟。

## Frigate 真实流结果与默认值

输入来自同一 Frigate 转发流：1280×720 H.264，ffprobe 的 `r_frame_rate=30/1`；
Thor 同时报告 `avg_frame_rate=25/1`，这些是探测字段，不保证源始终提供固定帧率。
服务以实际收到的新帧为准。默认 8 FPS 的本次短测结果：

| 设备 | 逻辑路数 | 各路实际 FPS | 编码 p95（ms） | 收帧到编码 p95（ms） | 候选通知（s） |
| --- | ---: | --- | ---: | ---: | ---: |
| Mac M2 Max | 1 | 8.00 | 43.6 | 107.7 | 0.457 |
| Mac M2 Max | 3 | 7.84 / 8.04 / 8.04 | 27.8–35.5 | 82.3–127.8 | 0.427–0.460 |
| Thor | 1 | 7.92 | 65.5 | 140.5 | 0.375 |
| Thor | 3 | 7.86 / 7.86 / 7.96 | 40.1–40.8 | 107.3–135.7 | 0.448–0.524 |

编码与收帧延迟为每路抽样统计，三路栏显示各路 p95 的范围。每阶段每路只触发一次
候选，通知列是这些单次结果，不是通知延迟的 p95 或上限；全部五张图、对账、重复
回执和摄像头删除事件均通过。8 FPS 测试所有设备各路均无 stale 健康采样。

先前 10 FPS 测试中，Mac 单路为 9.68 FPS，三路为 9.77 / 9.97 / 9.87；
Thor 单路为 9.90 FPS，三路为 9.29 / 9.09 / 9.09。Mac 的 10 FPS 单路阶段出现过
一次 stale 健康采样。Thor 三路的编码 p95 约每路 39 ms，三路合计已超过 100 ms
检测周期，因此没有把 10 FPS 继续作为全局默认。

当前默认每路 8 FPS，确认时间 0.3 秒，五帧间隔 0.075 秒；在本次三路条件下实际
频率更接近目标，也为调度留出余量。单路或更快配置可覆盖为 10 FPS，并观察实际
FPS、帧龄和处理时长。增加摄像头后重新测量，不承诺路数或负载变化后仍满足原频率。
这些结果支持本机收帧后争取 1 秒内通知；实际误报率、摄像头到 CLIP 的延迟与长时间
稳定性仍需现场观察，默认相似度阈值 0.9 尚未做场景标定。
